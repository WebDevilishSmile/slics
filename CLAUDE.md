# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this app is

SLICs replaces a paper binder that UPS Feeder drivers used to look up destination addresses/phone numbers. A driver enters a SLIC code and gets the address, a tap-to-open Google Maps link, a tap-to-call phone number, and driver-submitted comments about that location. It's a live production app used daily (not a demo), so changes to auth, data integrity, and the admin CRUD flows have real user impact — see `README.md` for the full product context.

## Commands

- `npm run dev` — start dev server (Next.js with Turbopack)
- `npm run build` — production build
- `npm run start` — run the production build
- `npm run lint` — ESLint (`next/core-web-vitals` config)

There is no test suite configured in this repo.

Environment variables: `.env.example` lists every key the code reads, with a one-line comment each — copy it to `.env` and fill it in. It is the only `.env*` file that is tracked (`.gitignore` has `!.env.example`); keep it current when a `process.env.*` read is added or removed.

## Architecture

**Stack:** Next.js 15 (App Router) + React 19, MongoDB (native driver, no ODM), NextAuth v5 (beta) for auth, MUI v7 for components, Tailwind for utility classes alongside MUI's `sx` prop, Emotion as the styling engine under MUI.

**Path alias:** `@/*` maps to the repo root (e.g. `@/lib/db/client`, `@/lib/db/slics`, `@/auth`).

**Where code lives outside `app/`:** `app/` is the route tree (plus `app/context/`); components are in `components/` at the root (`docs/archive/STRUCTURE.md` #21). `lib/db/` is the data layer (one module per collection, plus `client.js`); the rest of `lib/` is shared helpers, server and client (`serializers.js`, `format.js`, `rateLimit.js`, `geo.js`, `apiRequest.js`…); `hooks/` holds the client hooks; `theme.js` and `constants.js` sit at the root. There is no `utils/` folder anymore (`docs/archive/STRUCTURE.md` #15–20), so don't recreate it.

### Auth

NextAuth v5 is split across two files because of Edge runtime constraints:
- `auth.config.js` — Edge-safe config only (OAuth providers, JWT/session callbacks that don't touch the DB). Used by `middleware.js`.
- `auth.js` — full config: adds the Credentials provider (bcrypt password check), `MongoDBAdapter`, and JWT/session callbacks that hit the database for fresh `role`/`bmcMember`/`comments`. Its `auth()` is called only by `lib/authz.js` (below); `signIn`/`signOut` are still imported from `@/auth` directly.

The `auth.js` JWT callback returns `null` when the user row no longer exists, which makes Auth.js clear the session cookie — so deleting a `users` row (self-service via `DELETE /api/users/[id]`, or by hand) signs that user out everywhere on their next request. A *failed* lookup (Mongo unreachable) keeps the existing token on purpose; don't collapse the two cases. It also returns `null` when the row's `sessionVersion` is newer than the token's: a password reset or a change on `/profile` bumps it (`lib/db/passwordResets.js`, `docs/PASSWORD-RESET.md`), which signs the account out everywhere. Reset links are made by an admin on `/admin/users` (never their own, an admin's only by a super admin, never a super admin's), by `npm run password:reset-link`, or emailed by "Forgot your password?" on `/sign-in` (`POST /api/auth/forgot-password`, since 2026-10-12: 30 minutes, the same answer for every address, the email sent in `after()`; using one sets `emailVerified`). Only the token's hash is stored, and the token rides in the URL fragment so it stays out of logs. A link's origin comes from `siteOrigin` (`lib/siteOrigin.js`): `SITE_URL` in production, never the request's Host. The middleware's Edge callback has no DB lookup, so it still lets the request reach the page; the page's own `auth()` is what returns `null`.

Route protection happens at two levels:
- `middleware.js` — redirects unauthenticated users to the sign-in page, `/sign-in` (`auth.config.js` `pages.signIn`), for non-public paths, and separately gate-keeps `bmcMember`-only routes (e.g. `/history`, whose non-members go to `/sign-in` for the membership prompt). The page they wanted (path and query) rides along as `?callbackUrl=`, and signing in (Google or email) goes straight to it, or to `/home` (since 2026-10-12; it used to come back to `/sign-in` first). The membership prompt shows only when a signed-in non-member opens `/history`, which the middleware sends to `/sign-in`; a member on `/sign-in` is redirected on (`app/sign-in/page.jsx`). Always pass it through `safeCallbackUrl` (`lib/callbackUrl.js`), which only accepts a path on this site and never `/sign-in` itself (that would loop). The sign-in panel (`signIn/SignInPanel.jsx`) keeps its form in `?mode=signup|forgot`, so Back and reload keep it. Switching forms is a View Transition: each piece carries a `vt('…')` name (`signIn/signInModes.js`; one element per name at a time), the motion is the "Sign in, sign up, reset" block in `app/globals.css`, and the panel resizes with `utility/AnimatedHeight.jsx`. A new piece in a form needs a name, or it pops in. The middleware sends old `/signin` links and `/?callbackUrl=` (sign-in was on `/` until 2026-10-12) to `/sign-in`.
- `/` is the public landing page (`components/landing/`, since 2026-10-12): what SLICs does, how to start, and "Why you sign in" (what Google sign-in receives). Google's OAuth branding review reads it, so it must stay public, explain the app and link the privacy policy; keep "Why you sign in" in line with `/privacy`. A signed-in driver sees it too, with "Open SLICs" instead of "Sign in or sign up". Features that aren't open to every driver (covers) stay off it. Its hero shows a made-up SLIC card (`landing/ProductPreview.jsx`, static, never a real SLIC) that copies the /home card's look, so keep it in step when that card changes. The link preview is `app/opengraph-image.jsx`; `/opengraph-image` is in the middleware's `publicPaths` so crawlers get the picture, not the sign-in redirect.
- Inside API routes — every handler, reads included, starts with `const { session, denied } = await requireUser()` (or `requireArea('<area>')` for an admin tool, `requireSuperAdmin()` for the hub) from `lib/authz.js`, then `if (denied) return denied;` (401 `Unauthorized` / 403). ### API routes

Paths are a plural collection with an `[id]` item segment (`/api/slics`, `/api/slics/[id]`, `/api/comments/[id]/vote`; `docs/archive/STRUCTURE.md` #29), and multi-word segments are kebab-case (`/api/cover-bid-jobs`, `track-view`; #30). The signed-in driver's own routes are under `/api/users/me/` (#31). `app/api/newSlic`, `slic/[id]` (and `/pdf`), `comment`, `coverBidJob/[id]`, `coverBidJobs/**` and `user/**` are only aliases that re-export the new handlers, kept so an app opened before the 2026-10-08 renames keeps working. Never call them from new code; they'll be deleted.

Standard shape for `app/api/**/route.js` (see `app/api/slics/[id]/route.js`, `app/api/comments/route.js`):
1. `requireUser()` / `requireArea('<area>')` / `requireSuperAdmin()` from `lib/authz.js` first, for every method.
2. Validate route params / body, returning `NextResponse.json({ error }, { status })` on failure (400/401/403/404).
3. Delegate to a `lib/db/*.js` function inside a `try/catch`; log with `console.error` and return 500 on unexpected failure.

Every error response (status ≥ 400) has the body `{ error: string }` — clients read `data.error` and nothing else (`docs/archive/SUGGESTIONS.md` #14). Keep the string human-readable and don't include the raw caught error (`error.message`) in the body; it's already `console.error`'d server-side. A message the data layer means for the caller is thrown as `HttpError(status, message)` (`lib/httpError.js`), and the route's catch returns `errorResponse(error, fallback)`. Success bodies are not standardized: some routes return `{ success: true, data }`, some `{ message }`, some the document itself — check the route before adding a caller.

Rate limiting (`lib/rateLimit.js`) is a MongoDB-backed fixed-window limiter, deliberately **fail-open** (allows the request through if Mongo is unreachable — a limiter outage must not take down sign-up/commenting). Key it by user id where an authenticated action should be per-driver-not-per-network (drivers share building wifi), by IP for pre-auth endpoints like registration.

### Frontend structure

- `app/<route>/page.jsx` are route entry points; `components/<feature>/` holds the components for that feature area, mirroring route names (`admin/`, `bids/`, `comments/`, `covers/`, `drivers/`, `slic/`, etc.). Import a component as `@/components/<feature>/<Name>`; a relative path only for a sibling in the same folder (`./CommentPin`), never `../`.
- `components/layout/Providers.jsx` is the client-side provider tree: `SessionProvider` → MUI `AppRouterCacheProvider` → `ThemeProvider` (+ `CssBaseline`). Since 2026-10-15 the browser doesn't fetch the session: `app/layout.jsx` passes the one it read to `SessionProvider` (JSON round-tripped, as `/api/auth/session` would send it), and `refetchOnWindowFocus={false}`, because drivers switch apps all day and each return was a function call that made `/api/auth/session` the most-called route on Vercel's Hobby CPU budget. Don't turn it back on; server reads are the source of truth. `layout/SessionSync.jsx` re-fetches once when a later server render sees a different session (sign-out by server action, a new membership). `getSession()` is wrapped in React `cache()`, so a render reads the user row once however many components ask; treat the session it returns as read-only.
- **Links never prefetch** (since 2026-10-15). Every route renders on demand (the root layout reads the session), so a prefetch is a function call, and the closed header menu prefetched all its links on every page load. Import `Link` from `@/components/utility/NextLink` (next/link with `prefetch={false}`); the theme renders MUI `href`s through it, and ESLint refuses `next/link` anywhere else. The menu drawer mounts only while open (`ModalProps={{ keepMounted: false }}`).
- **Lookups don't go to the server.** On /home and /hubs, picking a SLIC moves the URL with `pushLookupUrl`/`replaceLookupUrl` (`lib/lookupUrl.js`, the browser's `history.pushState`, which Next.js keeps in step with `useSearchParams`), never `router.push`: that re-rendered the page on the server for every lookup. The page itself sends the SLIC list, the lookup count and the first SLIC's tip count once.
- **Drivers get SLICs only through `toDriverSlic`** (`lib/serializers.js`, since 2026-10-15), which names its fields. `serializeSlic` spreads the document, `createdBy`/`updatedBy` stamps included, so it's for admin pages only.
- `app/robots.js` serves `/robots.txt` as a static file (since 2026-10-15); before it, every crawler request rendered the 404 page in a function.
- Theme is `theme.js` (MUI `createTheme` with `colorSchemes.dark`, `cssVariables: { colorSchemeSelector: 'class' }`, `responsiveFontSizes`). Three custom palette keys exist beyond MUI's defaults, each defined in both schemes: `background.comment` (comment surfaces), `text.light` (footer/header text on the primary color), and `bmc` (the Buy Me a Coffee button, `color='bmc'` via `layout/BmcButton.jsx`). `background.opposite`/`text.opposite` were pruned when the floating mode toggle moved into the menu. Reuse these — or MUI's own keys — rather than hardcoding hex colors in components; add a new key in both `palette` and `colorSchemes.dark.palette` if you need another. Raw color values live in the `tokens` object at the top of `theme.js`. The app uses a seamless soft, embossed look instead of Paper elevations (see "Visual style" below): the shadow pairs are `theme.soft` (`panel`, `raised`, `raisedSmall`, `inset`, `insetDeep`, one value per scheme, built by `softShadow`: a brand-tinted shadow and a white highlight in light, a deep shadow and a faint highlight in dark), plus `overlay`, a plain drop shadow with no highlight for whatever floats over a backdrop. The sx helpers are in `components/utility/soft.js` (only inside a `<Paper variant='panel'>`, whose surface they match): `softRaised`, `softInset`, `softInputSx` (a pressed-in TextField with a placeholder, not a floating label) and `softPressSx` (pressed in while held or `aria-pressed`). Soft elements take the panel's own surface, overlay included, so only light and shadow set them apart.
- Shared constants (page sizes, layout dimensions, example doc shapes for reference) live in `constants.js`.
- Spacing in `sx` uses MUI spacing numbers, never rem strings: `mt: 2` is 1rem/16px (`theme.spacing` is the 8px default, root font size is the browser default). That applies to `m*`/`p*`/`gap*` and their responsive objects only — heights, `top`/`left` offsets and `fontSize` still take rem strings, because a bare number *there* means pixels. Careful with `width`/`height`: a bare number up to 1 is a fraction, so `width: 1` is 100%, not 1px; write `'1px'`. Plain `style={{ }}` objects (only `app/global-error.jsx`) are outside MUI and keep rem.
- Page-level widths come from the `theme.layout.width` scale (`docs/archive/UI-SUGGESTIONS.md` #19): `field` 30rem (a form control column), `panel` 32rem (the content column), `prose` 40rem (readable text), `wide` 55rem (sign-in/membership messaging, admin tables), `page` 1436px (`PageContainer`). Use `maxWidth: theme.layout.width.<step>` — never a new rem literal, and don't add a sixth step for a one-off; snap to the nearest. Table-cell/icon widths are component-local and not part of the scale.
- The main content panel is `<Paper variant='panel'>` (defined in `theme.js`, `docs/archive/UI-SUGGESTIONS.md` #17); call sites add only their delta (`justifyContent: 'center'`, `px: 2`). Don't re-inline the width/min-height/flex block.
- Page and section titles are `<Typography variant='sectionHeading'>` (`docs/archive/UI-SUGGESTIONS.md` #18) — h2, centered and capped at prose width, defined as a `MuiTypography` variant in `theme.js` and rendered as an `<h2>`. It no longer uppercases (#38), so write each title in the casing it should show ("SLICs", "SLIC History"). There is no heading wrapper component anymore; the app name on `/` and `/home` is a plain `variant='h1'`. The exception is the evolved look on `/help`, `/privacy` and `/terms` (see "Visual style"), whose titles are a left-aligned `variant='h3'` `component='h1'` at weight 800.
- Custom hooks live in `hooks/`, one `'use client'` file per hook, imported as `@/hooks/useX` — `useGeolocation`, `useAppleDevice`, `useMapsApp`, `useInstallPrompt`, `useCoverBidJobs`. Client helpers that aren't hooks (`tapHaptic`, `withViewTransition`, `tipsStore`) live in `lib/`. For "is this a phone", use `useMediaQuery(theme.breakpoints.down('sm'))` against the theme's breakpoints; the old `useIsMobile` hook (a private 768px cutoff) was removed in `docs/archive/UI-SUGGESTIONS.md` #29. Prefer adding a new cross-component browser-state hook there over duplicating logic in a component.
- `app/context/CommentRefreshContext.js` is the refresh lock for the *server-rendered* comment lists (profile page, admin user page): `CommentDelete` calls its `refresh()` (a `useTransition` around `router.refresh()`) and every delete button in the list disables while `isRefreshing`. The home-page "Driver tips" section (`components/comments/Comments.jsx`) is client-fetched and refetches its own thread instead — the two don't share state.

### Visual style: soft / embossed (match it in every UI change)

Since 2026-10-07 the app's look is a **soft, embossed (neumorphic) style in the existing colors**, and since 2026-10-08 every page uses it: /home (the lookup card, the SLIC search bar, the Driver tips), `/history`, `/places`, `/profile`, the landing page on `/`, sign-in and membership on `/sign-in`, `/about`, `/privacy`, `/terms`, `/covers`, the 404/error/redirect pages, the header menu and the footer. A tip listed outside its SLIC (a driver's tips on their profile and on the admin user page, every tip on `/admin/comments`) is one shared card, `comments/CommentCard.jsx`, with props for what differs (`slicName`, `author`, `canDelete`); the interactive tip in a SLIC's thread on /home is `comments/Comment.jsx`. The admin pages (index, SLICs, users, comments, drivers, covers, cover jobs, SLIC form, Planet Fitness) use it too; `softTableSx` styles their tables. **Any UI you add or change should match it**, not the older outlined/elevated MUI look. Restyle what you touch, and say so in the summary. The rules:

- **Inside a `<Paper variant='panel'>`**, build with the helpers in `components/utility/soft.js`:
  - `softRaised` for cards and tiles;
  - `softRaisedSmall` for pills and chips;
  - `softInset` for wells (an address, a reply list, a sort track);
  - `softInputSx` for text fields, selects and date pickers. Each is a well that `softFocus` presses deeper on focus, with a brand-blue hairline inside its edge (no outer glow ring; that read as a halo). A field in `error` gets the same hairline in the error color. It never has a floating label. A lone box takes a placeholder and an aria-label. A form field keeps its `label`, which `softInputSx` moves above the well (`places/PlaceFormDialog.jsx`). `PhoneField` takes it through `sx`; `SlicTagsField` is always soft;
  - `softPressSx` for anything tappable, which presses in while held and stays pressed while `aria-pressed`. It pins MUI's hover/focus background to the surface (on a phone `:hover` sticks after a tap and left controls gray). There's no ripple anywhere (`MuiButtonBase` `disableRipple` in `theme.js`); keyboard focus is the theme's `.Mui-focusVisible` outline in brand blue, `outlineColor: 'currentColor'` on the blue header. So don't put it on a colored control (a contained button, the blue header's icons): it would paint it surface-colored on hover;
  - `softListItemSx` for a row in a soft list (the header menu): a rounded row that presses in, with the current page (`selected`) pressed in and brand blue;
  - `softToggleSx` for filter chips that toggle (`aria-pressed`): raised when off, pressed in with brand-blue text when on;
  - `softContainedSx` on the one `variant='contained'` button, swapping MUI's drop shadow for the soft one.
  - A secondary button is `[softRaisedSmall, softPressSx]`. Dialog actions are `<DialogActions disableSpacing sx={{ px: 3, pb: 3, gap: 1.5 }}>` with a soft Cancel and the contained action, both `minHeight: '3rem'` (`drivers/DeleteDriverDialog.jsx`).

  The helpers are functions of the theme, which can't be passed from a server component to MUI's client components. In a server component, call one with the imported theme: `sx={softRaised(theme)}` (`about/AboutSection.jsx`, `signIn/SignIn.jsx`); the result is a plain object.

  **It's seamless.** The page, the `panel` Paper variant, the themed overlays (`MuiDialog`, `MuiPopover`/menus, `MuiDrawer`, the date picker's `MuiPickerPopper`) and every soft element share one surface, `background.default` with no overlay. Dialogs, the drawer and snackbars sit over a backdrop or content, so they take `theme.soft.overlay` (a drop shadow with no highlight); a soft highlight over a dimmed backdrop is a white halo. That's `#edf3fc` in light and the lifted `night` `#15181c` in dark (not near-black; shadows need something to fall on). Only light and shadow separate them: no borders, no outlined variants, no Paper `elevation`, no `elevation` on dialogs or menus. So the helpers work on the page itself as well as inside a panel (the search bar, `utility/SoftNotice.jsx`).
- **Info notices are `utility/SoftNotice.jsx`**: a raised card with a blue icon, the message, actions and an optional dismiss. Errors, successes and warnings are MUI Alerts, which the theme's `MuiAlert` override draws soft for every severity and variant: the surface, regular text, and the severity's color on the icon only. Inline they're an inset well; in a snackbar they float on `theme.soft.overlay`. Don't restyle Alerts per call site.
- **Color stays the theme's.** One solid brand-blue (`primary`, contained) element per card, its main action, sitting on `theme.soft.raisedSmall` instead of MUI's drop shadow. Everything else is surface-colored with `primary.main` icons and text. Status colors (error, the red "new" badge) keep their meaning. The shadow values are `theme.soft` in `theme.js`; tune them there, never per component.
- **Classy, not gimmicky.** Generous radii (16px cards and tiles, pill chips), even spacing (`gap` 1.5–3) so shadows have room, and restraint: one emboss level per element, never a raised card on a raised card. Nested content goes in an inset well.
- **The evolved look on `/help`, `/privacy` and `/terms`** (since 2026-10-12, the user's call after an Impeccable critique; whether it spreads further is undecided, `.impeccable/surfaces/app-help-page-jsx.md`). Same surface, colors and helpers, with:
  - titles left-aligned at weight 800 (`letterSpacing: '-0.02em'` on the h1), not centered `sectionHeading`;
  - content open on the page, not a stack of cards: each help guide (`help/HelpGuide.jsx`) and legal section (`legal/LegalSection.jsx`) is a heading and text, and only its picture or notes are embossed;
  - one raised card at each end at most, on the tighter `theme.soft.raisedTight` (`softRaisedTight`, 4px/10px) with a 40px radius (`borderRadius: 5`): /help's example SLIC card and "Still stuck?", the legal pages' "The short version" (`legal/LegalSummary.jsx`) and Contact (`legal/LegalContact.jsx`), each closing card holding the page's one contained button;
  - a link landing on a guide or section rings it in brand blue (`.help-guide:target`, `.legal-section:target` in `app/globals.css`; the ring holds without motion under reduced motion).

  /help opens on a made-up SLIC card (`help/ExampleSlicCard.jsx`, never a real SLIC; keep it in step with the /home card like `landing/ProductPreview.jsx`) whose controls carry numbered pins linking to their guides (`help/PinnedControl.jsx`: pressed in while held via `:active`, `tapHaptic()` on activation). A guide with a `screen` (`help/guides.jsx`) shows that screen dimmed with the one control it explains ringed and flagged TAP: a card control, or a picture from `help/HelpScreens.jsx` (search, menu, post a tip, report). Rename a button and those pictures need the new label too. `/privacy` and `/terms` share `legal/LegalPage.jsx`: the title and effective date, a prose column and, from `lg`, a sticky "On this page" rail; each page lists its section titles in `SECTIONS`, which must match its `LegalSection` titles or the anchors break.
- **Don't trade away accessibility for the look.** A pressed or selected state also changes the icon (filled vs outlined) or the color, not just the shadow. Focus rings stay visible. Touch targets stay at least 40–48px. Text keeps AA contrast.
- **Loading states** are `<Skeleton>`s shaped like the content, inside the same soft shapes (`home/SlicCardSkeleton.jsx`, `layout/LoadingFallback.jsx`). No "Loading..." text. Content behind a `utility/HydrationGuard.jsx` renders only in the browser, so pass the guard a `fallback` skeleton the same height, or what the server sends first jumps when it arrives (`home/LookupSkeleton.jsx` on /home and /hubs, within a few px).
- **Motion** is progressive enhancement and always respects reduced motion.
  - Easing comes from `--ease-out` / `--ease-spring` (`app/globals.css`, mirrored as `theme.transitions.easing.out` / `.spring`). Durations are MUI's `theme.transitions.duration`.
  - A global `prefers-reduced-motion: reduce` floor stills everything, so don't add per-component reduced-motion code for CSS animations. SVG animation (SMIL) is the exception: the floor can't reach it, so `utility/AnimatedSlicsMark.jsx` swaps itself for the still mark with its own media query.
  - Animate a state change between two renders with `withViewTransition` (`lib/viewTransition.js`) and a `viewTransitionName` on the element. Only one element may hold a name at a time. The page root has no snapshot (`:root { view-transition-name: none }`), so only named elements animate.
  - For an element appearing for the first time, add the `enter` class (a CSS `@starting-style` fade with a lift; set `--i` on list items to stagger them). It never replays on re-render. A Paper needs nothing extra: `.MuiPaper-root.enter` already outranks MUI's own Paper transition.
  - Tap feedback: add the `pop` class to an icon as it mounts for a small spring pop (only on the tap, never on load), and call `tapHaptic()` (`lib/haptics.js`; Android-only, feature-detected) on the actions that matter. Confirm in place, by changing the control itself plus a polite live region, rather than with a toast (see the copy button in `home/TitleAddress.jsx`).
- **Check light and dark at phone width** for every change. The dark scheme's emboss is subtler by design.

### PWA / home-screen install

The app is installable (manifest + HTTPS) and deliberately has **no caching service worker**: installability no longer requires one, and a stale cache is the one PWA failure that outlives a deploy. Its only service worker is `public/sw.js`, for push notifications (since 2026-10-10, `docs/PUSH-NOTIFICATIONS.md`). Rules for it:
- It handles `push` and `notificationclick`, plus `skipWaiting`/`clients.claim`. It has **no `fetch` handler, ever**.
- It's registered only inside the tap that turns notifications on (`hooks/usePushNotifications.js`), never on page load, and unregistered when they're turned off.
- Every notification's payload is written in `lib/pushEvents.js`, one `notifyX()` per kind, called inside `after()`. They go through `sendPushToAdmins(type, …)` / `sendPush` (`lib/push.js`), which never throw and log each send to `push-log` (90 days, no recipient ids). `sendPush` hashes each `tag` into the `Topic` header: Apple refuses a topic whose length can't be base64 (`BadWebPushTopic`), which kept two kinds off iPhones until 2026-10-14. A payload is lock-screen safe: a SLIC number or a week and what happened, never an address, a phone number, another driver's name or a tip's text (Buy Me a Coffee: the kind and the amount).
- Subscriptions are rows in `push-subscriptions` (`lib/db/pushSubscriptions.js`), one per device. Admins only, until the super admin's "Notifications for every driver" switch (`pushOpen`, `/admin/super/features`; `PUSH_OPEN` in `constants.js` is only the default) opens them to every signed-in driver (stage 2, built 2026-10-14 with the switch off). Check it with `canUsePush(session)` / `requirePush()` (`lib/authz.js`), like Covers. The toggle on `/profile` (`profile/PushNotifications.jsx`) turns a device on, and each driver picks the kinds under it (`profile/PushTypeSwitches.jsx`), per account (`users.pushPrefs`). The kinds are `PUSH_TYPES` (`constants.js`), each with an `audience`: `driver` (replies on your tips, comments on your places; on by default, sent through `getDriverPushAudience`, which counts only admins while the switch is off), `admin` or `superAdmin`. A new kind gets an entry there and a `notifyX()`, and is off by default unless it's a driver kind. Job changes and SLIC reports default on. A reply push goes first and its recipients are skipped for the admin kind, so nobody gets two for one reply. Signing out turns the device off (`turnOffThisDevice`, `lib/pushDevice.js`). Drivers are offered it only by a nudge after they post (`push/PushNudge.jsx`), never on page load, and by the `/help` guide, which a guide's `feature: 'pushOpen'` hides while the switch is off. The browser/status-bar color is `statusBarColors` in `theme.js` (the header's color in each scheme, computed, never a literal): `app/layout.jsx` emits a light/dark `themeColor` pair and `layout/ThemeColorSync.jsx` re-points both metas when a driver pins a mode with the menu switch. The manifest is `app/manifest.js` (served at `/manifest.webmanifest`, `start_url: '/home'`); the icons (`app/apple-icon.png`, `app/favicon.ico`, `public/maskable-icon-*.png`, `public/android-chrome-*.png`, and `public/apple-touch-icon*.png`, the root paths iPhones ask for, which used to 404) all come from `npm run icons:generate` (`scripts/generateIcons.mjs`), which renders the full-bleed master `public/slics-icon.svg` at 100% — regenerate, never hand-edit. The header and menu use the glyph alone, `utility/SlicsMark.jsx` (white via `text.light`). `utility/AnimatedSlicsMark.jsx` (since 2026-10-12) is the mark drawing a question mark, erasing it and drawing the S: once on the 404 page, and on a loop (`loop`) at the top of /help. `public/slics-animated-logo.svg` is the loop as a file for use outside the app, and `public/slics-question-icon.svg` the question mark alone. Its `story='heart'` starts as a heart that beats twice, then the dot comes out of its line, erases it and draws the S: once, on the thank-you note's letterhead after Tiago signs (`support/ThankYouNote.jsx`; the two share their timing), where the letter still in the envelope holds the heart with `paused` (the first frame, nothing playing). `public/slics-animated-heart-logo.svg` is its loop as a file and `public/slics-heart-icon.svg` the heart alone. Its `story='dot'` (since 2026-10-16) is the logo's dot alone, which takes a breath, then draws the S and lands on the logo: once, on the welcome note's letterhead after Tiago signs (`staff/WelcomeNote.jsx`); `public/slics-animated-dot-logo.svg` is its loop as a file. All of them copy the master's S path, so change them together. An iPhone keeps the icon it was installed with, so after an icon change press "Ask again" on `/admin/super/features` (`ICON_CHANGED_AT` in `constants.js` is the default): `install/NewIconNotice.jsx` then asks drivers in the installed iPhone app, on /home, to remove and re-add it, until they dismiss it (`users.iconNoticeDismissedAt`, `POST /api/users/me/icon-notice`; on the account because removing the app wipes its storage). Install detection is `hooks/useInstallPrompt.js`: Chrome's `beforeinstallprompt` is stashed on `window.__slicsInstallPrompt` by an inline script in `app/layout.jsx` (it can fire before hydration); iOS has no prompt, so `components/install/IosInstallDialog.jsx` shows the Share → "Add to Home Screen" steps instead. The nudge on `/home` snoozes itself via `localStorage` for 30 days; the header-menu entry is the permanent path.

## Known issues / conventions to be aware of

`docs/README.md` indexes the docs folder and its conventions. `docs/TODOS.md` is the hub: open work of every kind and every idea, one line each (Inbox → Ideas → Next → Now, plus Waiting, Security and Housekeeping), linking to the doc that explains how. When the user asks to add something to the list without naming a section, it goes in its Inbox. Checked-off items move to `docs/archive/DONE.md`. The other docs explain: a plan doc per staged feature (a later stage goes in the same doc), design notes for ideas in `docs/RECOMMENDATIONS.md`, and security detail in `docs/SECURITY.md` (whose status table was re-checked against the code 2026-10-10). Collections are mapped in `docs/DATA-MODEL.md`, and deploys, env vars, cron/webhooks, scripts and secret rotation in `docs/OPERATIONS.md`; update those two in the same commit as a change that makes them wrong. Finished punch lists live in `docs/archive/` under their original filenames, because code comments cite them by name and item number. Never renumber an item or rename a cited doc.

`docs/archive/SUGGESTIONS.md` is a checked-off punch list of security/perf/quality issues found in this codebase — every item is now done, but the entries still document the reasoning behind a lot of current conventions (auth checks per route, `_id`-keyed slic routes, `{ error }` bodies), so read the relevant item before changing one of those areas. `docs/archive/STRUCTURE.md` is the (archived) list for file/folder organization and API path naming; its leftovers are in `docs/TODOS.md` → Housekeeping. The SLIC create/edit form and its field components live in `components/slicForm/` (one `SlicForm` with a `mode` prop); generic fields shared across features (currently `PhoneField`) live in `components/form/`.

`docs/archive/UI-SUGGESTIONS.md` (called `THEME.md` until 2026-10-03; item numbers unchanged) is the equivalent punch list for styling and UI, archived 2026-10-10 with its leftovers (#54, #55, the #52 bottom-nav decision, #57's small items) moved to `docs/TODOS.md`. Read the relevant item before changing anything visual. Part 1 (#1–#30) is theme plumbing. Part 2 (#31+) is a UI review: accessibility, phone layout, the lookup screen, motion and navigation, with a suggested order at its top. Part 1 is complete (2026-10-07); its rules still apply. Text sizes come from Typography variants (`variant=` or `typography:` in `sx`), never one-off `fontSize` rem values; icon sizes are exempt. Layers come from `theme.zIndex` by name (e.g. `zIndex: 'stickyBar'`). `layout/Container.jsx` owns the full-height shell, and `PageContainer` is only the content column. The fixed header is cleared by an empty `<Toolbar />` spacer in `header/Header.jsx`, not by page margins. Sub-pages have no Home/Back buttons of their own: `header/HeaderBar.jsx` shows a back arrow and the page name for any path in its `PAGE_TITLES` list (add new pages there), and the logo links home (#52). Because #1–#3 are done, the theme is no longer inert: `<body>` carries `font.variable`, meaning `theme.typography.fontFamily` now controls the body font (to change the app font, swap the `next/font` loader in `app/layout.jsx`), and `MuiButton` is a single key again. Two conventions worth keeping: **one key per component** in `theme.components` — duplicate keys replace rather than merge, silently — and **palette paths like `'primary.dark'` only work in `sx`**, never in `styleOverrides` or `variants[].style`, where they emit invalid CSS the browser drops. Use a theme callback (`({ theme }) => ({ color: theme.vars.palette… })`) in those positions. Note `MuiButton` deliberately sets no colors; MUI's own variant styling is already color-prop-aware (see the comment in `theme.js`). Colors have a single source of truth: the MUI theme. `app/globals.css` and `tailwind.config.mjs` define no palette of their own (`docs/archive/UI-SUGGESTIONS.md` #10); CSS that needs a theme color reads MUI's emitted variables (`var(--mui-palette-…)`), which already follow the color scheme.
